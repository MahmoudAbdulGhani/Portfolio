## Origin and durable correction

- **Component:** `src/components/landscape/ProfilePage.tsx` hardcoded all three disclaimer paragraphs/spans. They were not database prose. Removed from the DOM, including hidden tabs; not merely hidden with CSS.
- **Live API/database fields:** read-only public GETs returned raw CMS records. Digital Hub `description` began “Completing an intensive…” while `details` and CV bullets said “Completed…”. Education had a degree/provider/dates with no details. Angular already had the correct independent-study title/provider. No live database or CMS field was changed.
- **Client:** `src/lib/hooks.ts` normalizes each API result through `shared/content-integrity-runtime.js`. Previously that module changed both Digital Hub “Completed” and “Completing” to “Participated”; every learning record received unverified completion metadata. The normalizers now apply the owner-confirmed facts after every fetch/refetch, including stale CMS variants. Reload tests use the unchanged raw responses, not pre-cleaned fixtures.
- **CV:** `server/src/lib/cv-config.js` already applied the same experience/training normalizers after resolving configuration. Education now uses the shared copy rules too, while retaining its resolved explicit date override. Both database-backed reads and the committed static catalog use this path; the historical bootstrap catalog is not rewritten and no client API-error fallback is added.
- **Internal evidence:** `learningEvidence.completion.status` is `owner-confirmed` only for the identified LIU Computer Science bachelor degree and Digital Hub full-stack record. Certification stays unverified. Unknown records keep their evidence/recorded claims; public descriptions omit internal disclaimers and unsupported completion assertions, preserving topic clauses. Dates/titles/links never establish independent certification. Normalization is idempotent and does not mutate the source record.
- **Assistant consistency:** the shared learning instruction accepts owner-confirmed completion for ordinary background summaries, keeps unknown summaries factual, and reserves explicit verification caveats for actual verification questions. Project attribution/security safeguards and provider configuration are unchanged. JSON/SSE tests use mocked provider transport; no live AI request is made.
