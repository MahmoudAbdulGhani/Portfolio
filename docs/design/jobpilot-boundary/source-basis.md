# JobPilot profile boundary — source basis

Inspected on 11 October 2026. Portfolio baseline: `2c00c354d7b6c727f26efb4fdaaabce4f9212588`. JobPilot source revision: `344b0d77d3d3525e8617df0a48e303055fbb024f`, available in the local private checkout. Inspection was read-only; no JobPilot service, provider, mutation endpoint or database was executed.

The existing portfolio case study in `shared/case-study-runtime.js` describes the same boundary. Its former static “The profile save boundary” figure is replaced by the reusable demonstration in the JobPilot reader. The Collection uses that component too; it does not introduce a competing architecture diagram. Existing engineering disclosures and source links remain available.

| Relationship | Inspected implementation | Demonstration scope |
| --- | --- | --- |
| Confirmed source information | `_prepare_generation` requires a successful CV extraction with `reviewed_at`; generation records its confirmed text, review time and hash. | A clearly fictional, fixed sample CV says “Location: Tripoli”. No extraction or generation is simulated. |
| Confirmed/saved profile vs proposed changes | `_merge_changes` starts from the current candidate profile. `review` returns `current_profile`, `proposed_profile`, changed fields and the current profile revision without applying them. | Saved Beirut and proposed Tripoli remain distinct. Propose and Review cannot change the saved value. |
| User review | `review` supplies the proposed/current comparison; `apply` accepts the reviewed profile revision. | Review is a separate intentional action, followed by an explicit Accept action. |
| Profile revision | `profile_revision` uses `updated_at`. Under owner/suggestion/profile row locks, `apply` compares the current revision with the reviewed revision and raises a conflict if they differ. | A browser-local counter illustrates this rule. Changing saved information to Byblos makes the Beirut review stale; attempted acceptance is blocked. A new review compares Byblos with Tripoli. This is not a transaction or concurrency simulation. |
| Confirmed-CV freshness | `_check_source` compares the extraction’s review time and content hash; apply performs this check under a row lock. Changed CV text requires fresh suggestions. | Explained in disclosure. The optional action changes the profile only, so another profile review is appropriate. It does not claim another review alone repairs a changed CV. |
| Accepted information | `apply` persists accepted profile fields and provenance, marks the suggestion set applied, stores its selection hash/result, and commits. | Only a successful approval updates the local saved location and aligns the ivory plate. There is no persistence or provenance storage. |
| Repeated accepted requests | Under the suggestion lock, an already-applied set with the identical selection hash returns the existing record; different selections raise a conflict. | The reducer ignores repeated approval after acceptance. Disclosure explains the source rule; network replay/idempotency is not simulated or runtime-tested. |

The demonstration establishes a communication pattern, not production capability, performance, hiring outcomes, personal ownership or live backend verification. Values are fictional and kept in React memory. Navigating away or closing/reopening starts a new sample. Reset explicitly retires the current review.

The sculpture uses the existing `/landscape/jobpilot-sculpture.webp` twice through complementary SVG masks. One foreground ivory plate rotates 3.5° in the image plane about the pictured lower support, over 380ms, and settles into its original position after approval. The rest and accepted silhouette use the original pixels. This is photographic articulation, not newly reconstructed 3D or a literal architecture drawing. No new artwork is introduced. The existing WebGL opening, model geometry/materials, screenshot controls and routes remain intact. Reduced motion updates the same pose immediately; the HTML comparison and controls remain available when WebGL is unavailable.
